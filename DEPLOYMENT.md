# Deployment Guide

Step-by-step guide to host the entire stack for **free** on:

| Component   | Provider                | Free tier                 |
|-------------|-------------------------|---------------------------|
| Database    | **Neon** (Postgres)     | 0.5 GB storage, persistent |
| Backend API | **Render** (Web Service)| 512 MB RAM, sleeps after 15 min idle |
| Frontend    | **Vercel** (Static)     | 100 GB bandwidth          |
| LLM         | **Groq Cloud**          | Generous free tier        |


Total cost: **$0**.

## 2 · Create a free Postgres database on Neon

1. Sign up at <https://console.neon.tech> (free, no card needed).
2. Click **Create Project**.
   - Postgres version: 16 (default)
   - Region: pick the one closest to your Render region (US East works for most)
3. After creation, go to **Dashboard → Connection Details**.
4. Copy the **Connection string** that looks like:
   ```
   postgresql://your_user:your_password@ep-xxxx-xxxx.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
   Save it — you'll paste it into Render in the next step.

> The app's `database.py` automatically rewrites `postgres://` → `postgresql+psycopg2://`
> and adds connection pooling, so the same Neon URL works without code changes.

---

## 3 · Deploy the backend to Render

### Option A — One-click via Blueprint (recommended)

1. Go to <https://dashboard.render.com> and click **New → Blueprint**.
2. Connect your GitHub repo. Render auto-detects `backend/render.yaml`.
3. Click **Apply**.
4. Once the service is created, open it and set these environment variables
   under **Environment**:

   | Key               | Value                                                 |
   |-------------------|-------------------------------------------------------|
   | `DATABASE_URL`    | (paste your Neon connection string from step 2)       |
   | `GROQ_API_KEY`    | (your Groq key from <https://console.groq.com/keys>)  |
   | `FRONTEND_ORIGIN` | `https://your-app.vercel.app` (will get this in step 4)|

   `SECRET_KEY` was auto-generated by Render — leave it.

5. Click **Manual Deploy → Deploy latest commit** to trigger a build.
6. Once it shows **Live** (~5–8 min), open the URL Render gives you, e.g.
   `https://health-risk-api-xxxx.onrender.com` — you should see a JSON
   response with `diseases_loaded` listing all 6 models.
7. Visit `/health` — it should report `database.connected: true` and list
   your engine as `postgresql`.

### Option B — Manual web service

1. **New → Web Service** → connect repo
2. Root directory: `backend`
3. Runtime: Python 3.12
4. Build command:
   ```
   pip install -r requirements.txt && python -m ml_training.train && python -m scripts.init_db
   ```
5. Start command:
   ```
   uvicorn app.main:app --host 0.0.0.0 --port $PORT
   ```
6. Add the same env vars as above.

## 4 · Deploy the frontend to Vercel

1. Edit `frontend/vercel.json` and replace `YOUR-RENDER-SERVICE.onrender.com`
   with your real Render URL from step 3.

   ```json
   {
     "rewrites": [
       { "source": "/api/:path*", "destination": "https://health-risk-api-xxxx.onrender.com/api/:path*" },
       { "source": "/(.*)",       "destination": "/index.html" }
     ]
   }
   ```

   Commit and push:
   ```bash
   git add frontend/vercel.json
   git commit -m "wire vercel proxy to render"
   git push
   ```

2. Go to <https://vercel.com/new>, import your repo.
3. Set **Root Directory** to `frontend`.
4. Framework preset: Vite (auto-detected).
5. Click **Deploy**.
6. After ~1 min you'll get a URL like `https://your-app.vercel.app`.

7. **Copy that URL back to Render** — go to your Render service →
   Environment → set `FRONTEND_ORIGIN` to the Vercel URL → save.
   This re-deploys with proper CORS.

## 5 · Verify everything works

1. Open `https://your-app.vercel.app`
2. Click **Sign up** → create an account
3. Go to **Predict** → run a heart disease prediction
4. Go to **Reports** → upload a sample PDF
5. Go to **Chat** → ask "Build me a 7-day diabetic meal plan"
6. Open Render's `/health` endpoint to confirm Postgres is connected

If `/health` reports `models_loaded: []`, click **Manual Deploy** on Render
again — sometimes the model training step needs an extra restart.

## Common gotchas

| Symptom                                    | Fix                                                                 |
|--------------------------------------------|---------------------------------------------------------------------|
| `psycopg2.OperationalError: SSL required`  | Make sure Neon URL ends with `?sslmode=require`                     |
| CORS errors in browser console             | Set `FRONTEND_ORIGIN` on Render to the exact Vercel URL (no slash)  |
| 401 Unauthorized after login               | Check that `SECRET_KEY` didn't change between logins                |
| Render service is slow on first request    | Free tier sleeps after 15 min idle — first hit takes ~30s to wake   |
| Uploaded PDFs disappear                    | Render free tier filesystem is **ephemeral**. Upgrade to a paid disk, or move uploads to S3/R2 if you need persistence. The extracted text & values are still saved in Postgres. |

## Local development still works

Your local `.env` keeps using SQLite — just don't commit it. To switch to
Neon locally for testing, set `DATABASE_URL` to the Neon URL and run:

```bash
python -m scripts.init_db          # creates all tables in Neon
uvicorn app.main:app --reload
```

You can confirm which DB you're hitting at any time via:
```
GET /health
```
